# 原稿紅筆（第三階段：老師端）

稿紙代繳交、經過[逐格辨識](grid-ocr.md)的作文，批改頁左邊換成**拉正的原稿**，紅筆畫在學生的字上；
老師在原稿上確認錯字，確認過的才算分、送給[簡易批改](simple-grading.md)的 AI。

這一階段只做**老師端**（使用者決定，2026-11-20）。學生看到的東西不變 —— 發還後學生看自己的原稿加紅筆是下一步。
流程與畫法搬自 1Campus Write 的原稿批改頁（規格書「步驟4_原稿批改頁」、docs/adr/0011）。

---

## 畫面

**左邊**：拉正的原稿（`handwriting_grid_result.page_image_files`），上方可以切回「辨識文字」（原本的樣子、校對也在那裡）。
多頁時一頁接一頁往下排；可以放大到 300%，放大後在框裡按住拖曳。

| 紅筆 | 畫法 | 誰看得到 |
|---|---|---|
| 確定的錯字 | 紅圈，正確的字用楷書寫在行間 | 老師（之後學生） |
| 老師加的錯字 | 同上 | 老師（之後學生） |
| 待確認的錯字 | 紫色虛線圈加「?」 | 只有老師 |
| 否決的錯字、格式提醒 | 灰色虛線 | 只有老師 |
| 格式提醒 | 段首空兩格：紅色折角＋「空兩格」；標點在行首：紅框＋「移上行」 | 老師（之後學生） |
| 亮點 | 行間的綠色波浪線 | 老師（之後學生） |
| 密圈 | 行間的綠色小圈 | 老師（之後學生） |
| 建議 | 左側虛線 | 老師（之後學生） |

紅筆畫在**行間**：聯合報國中稿紙行間 3mm、聯合盃 4mm，和會考稿紙一樣；學測稿紙沒有行間，畫在格子右側裡面。
每個標記有編號（直書的閱讀順序），和右邊的便條一樣，點一下互相跳過去。格式提醒照樣框出位置，但不佔編號。

**右邊**：簡易批改區塊下面是「原稿紅筆」便條，老師可以：

| 對象 | 能做的 | 結果 |
|---|---|---|
| 待確認的錯字 | 是錯字／改正確的字／不是錯字 | 處理完自動跳到下一個待確認 |
| 系統標的錯字 | 改正確的字／不是錯字（可以復原） | |
| 原稿上任何一個字 | 點一下，填正確的字（說明可寫可不寫） | 算確定的錯別字，標「老師加的」 |
| 老師加的錯字 | 改正確的字／刪掉 | |
| 格式提醒 | 不是格式問題（可以復原） | |

- **每按一下就存**（`manuscript_mark_decision`，migration 013），和批改結果分開：重置批改不會清掉。
- **發還之後鎖住**（API 回 409），要改先收回發還。
- 按「AI 批改」時還有待確認的錯字，先提醒（不擋）：確認過的才算分、送 AI，先看完就不用因為錯字重新評分。

## 「確定的錯別字」只有一份

系統有把握、老師沒有否決的錯字，加上老師確認的、老師加的（`apps/api/src/lib/manuscript/marks.ts` 的 `mergeManuscriptMarks`）。
原稿畫面、送簡易批改 AI 的錯字清單、批改頁的辨識摘要、重新評分的基準，都用這一份。
**待確認的不算分、不送 AI。**

重複的錯字標記只算一個（`dedupeMarks`）：同一格被標兩次、或錯字表和 AI 對同一個詞建議同一個字卻標在隔壁格，留錯字表的。

## 老師加的錯字落在卡片引用上

通常是辨識把學生寫錯的字讀成了正確的字，系統以為這句沒問題就給了卡片。老師加了錯字之後：
密圈整張先拿掉；亮點、建議只拿掉引用和畫線；成語只拿掉那一個。刪掉那個錯字就恢復。
評語裡也提到那句時，只提醒老師自己看，不自動改字（評語是老師可以改的文字）。

## 重新評分

批改當下的錯字狀態存在 `simple_grading_result.detail.baseline`。之後老師改了錯字或格式，
「**3 個以上錯字或段首沒空兩格**」這條和批改時不同（變成符合、或不再符合）就在批改面板提醒「重新評分」。
- 3 個是 1Campus 會考版定下的門檻；聯合報的批改規範把錯別字與格式放在第四向度，4 級分的描述是「有一些錯別字及格式（如段首未縮排兩格）」，先沿用。
- 按下去先確認，再用目前確定的錯字重跑一次簡易批改，**存成新的一版：級分與評語都換掉**（老師改過的評語也會被換掉）。
  1Campus 是只換分數、卡片不動；這邊的卡片併在評語裡，沒辦法只換一半。
- 舊的批改結果沒有基準，不提醒。

## API（只給老師；學生端沒有）

| 端點 | 用途 |
|---|---|
| `GET /service/instructor/grading/:id/manuscript` | 每頁拉正的圖、有字的格子位置（圖上的像素）、合併後的標記、目前的錯字狀態。沒有逐格辨識回 `{ available: false }` |
| `GET .../manuscript/pages/:n` | 拉正的稿紙圖。用伺服器的 GCS 權限讀（bucket 之後不公開也能用；本機假儲存也讀得到），`Cache-Control: private` |
| `POST .../manuscript/decisions` | `{ target, cellKey, action, correct?, note? }`，回傳更新後的標記。標記已經變了回 409、說不通的動作回 400 |
| `POST /service/instructor/grading/:id/regrade` | 重新評分。還沒用簡易批改批過、已發還都回 409 |

範圍一律走 `courseScopeOf`：別班的老師 404。

## 楷書字型

正確的字用**全字庫正楷體**（數位發展部，依台灣國家標準字形）：學生照著紅字訂正，字形一定要是台灣標準寫法
（1Campus 用過悠哉字體，「啟」被畫成「啓」才改的）。

- 字型檔：`apps/web/public/fonts/tw-kai/`（只留 Big5 常用＋次常用字，切成 133 塊 woff2，約 9MB；瀏覽器只下載畫面上用到的字）。
  第一次打開原稿才載入。從 1Campus Write 複製；全字庫改版時用 `services/handwriting-ocr/tools/build_tw_kai_web.py` 重新產生。
- 授權：全字庫可擇一用政府資料開放授權條款或 **SIL OFL 1.1**，這裡用 OFL 1.1，全文 `apps/web/public/licenses/tw-kai-font-OFL.txt`。
  不用教育部標準楷書：它的授權是 CC 姓名標示－禁止改作，切成小檔算改作。

## 部署

正式庫依序套 011、012、`013-manuscript-mark-decision.sql`（**都要在程式上線之前**）。不用新的環境變數。

## 還沒做

- **學生端**：發還後學生看自己的原稿加紅筆、不再看辨識文字（1Campus 的「我的原稿」），連帶下載報告、AI 學習分析怎麼處理。
- 批次批改（批改清單一次批全班）還有待確認的錯字時，沒有先提醒（單份「AI 批改」有）。
- 名冊上標「錯字待確認 N」、原稿頁「下一份」（1Campus 的兩段式：先全班看錯字，再一次批改）。
- 實際印出來、手寫、拍照的稿紙還沒走過一次（本機的測試稿紙是模擬的，辨識文字是模擬 AI 填的）。
