## 一、想請你做的事（依順序）

### 1. 重新部署辨識服務 `handwriting-ocr`

多了一支 `POST /seat-scan`（讀座號），稿紙的版面也改了，所以要重新部署。

```bash
cd services/handwriting-ocr
gcloud run deploy handwriting-ocr --source . --region asia-east1 \
  --no-allow-unauthenticated --memory 2Gi --cpu 2 --timeout 300 --concurrency 4
```

- **不用新的環境變數、不用 migration、不用新的權限。**
- 如果這個服務之前還沒部署過（稿紙逐格辨識那一批，`action-items.md` 的 0.15），就照
  [`docs/grid-ocr.md`](../docs/grid-ocr.md) 的「部署」從頭做一次，這次的修改不需要額外的步驟。
- 部署後確認新的路由有上去（Cloud Run 上 `/healthz` 打不到，改打這支）：

  ```bash
  # 預期回 400 {"error": "沒有收到照片"}；回 404 代表部署到的是舊版
  curl -X POST -H "Authorization: Bearer $(gcloud auth print-identity-token)" \
       -H "Content-Type: application/json" -d '{}' <服務網址>/seat-scan
  ```

### 2. 部署 API／前端（`npm run deploy`）

- 後端多一支路由，前端多一個視窗與一個相依套件 `pdfjs-dist`（`package-lock.json` 有變）。
- `grid-ocr-job` 用的是同一個映像檔，照慣例一起換：`gcloud run jobs update grid-ocr-job --image ...`。
- API 沒有設 `GRID_OCR_SERVICE_URL` 時，「整疊掃描」的按鈕還是看得到，但讀座號會回
  「稿紙辨識服務還沒設定」。**所以第 1 步要先做。**

### 3. 用真的掃描機測一次（最重要，我們這邊做不到）

目前所有的測試都是電腦合成的：稿紙是程式畫的，座號是程式塗的黑色橢圓。
**沒有任何一張真的紙經過真的掃描機。** 請幫忙：

1. 從測試站的《我的稿紙》下載新的稿紙（國中稿紙、會考、學測都有座號劃記了），各印幾張。
2. 請人手寫幾行字、塗座號（2B 鉛筆、原子筆各試幾張），有寫背面的也要有。
3. 用掃描機**雙面**掃成一份 PDF（建議 200dpi）。
4. 批改作業 → 批次代繳交 → 右上「整疊掃描」→ 選 PDF → 核對 → 送出 → 開始辨識。

請特別看這幾件事，有任何一項不對請告訴我們：

| 要看的 | 為什麼 |
|---|---|
| 座號讀得對不對（尤其是鉛筆、塗得比較淡的） | 門檻是用合成的圖調的，真的筆跡沒驗證過 |
| 掃描機裁邊之後，四角的黑色小方塊還在不在 | 少一個角那一份就不能送，只能重掃 |
| 分份對不對（第 2 頁有沒有接到對的人後面） | 靠的是掃描順序＋稿紙上記的頁碼 |
| 一班 30 人雙面（60 頁）大約要等多久 | 我們估一兩分鐘，沒有實際量過 |
| 彩色 300dpi 的大檔會不會失敗 | 一次送 4 張是照 API 的 20MB 上限估的 |

### 整疊掃描怎麼運作

```
老師選 PDF ──► 瀏覽器把 PDF 展開成一頁一張圖（PDF 本身不上傳）
          ──► 每 4 張一批 POST /service/instructor/assignments/:id/seat_scan     ← 新的，只讀不寫
                 └─► API 轉給辨識服務 POST /seat-scan（不用 AI，一頁約 0.5 秒）
          ──► 前端分成一人一份、照座號配人，老師核對
          ──► 每位學生 POST /submissions/ocr_proxy                              ← 原本的，沒有改
          ──► 老師按「開始辨識」                                                ← 原本的，沒有改
```

- 新的那支 API **不存照片、不寫資料表**，只檢查「這份作業在不在他看得到的範圍」（`courseScopeOf`）。
  真正寫入時走原本的 `/ocr_proxy`，名冊與範圍在那裡照舊檢查。
- 送出之後的辨識、簡易批改、原稿紅筆**一行都沒改**。
- 是從 1Campus Write 的 `feat/batch-scan` 搬來的（那邊也還在搶先測試、沒合併進 main）。

### 設計上最在意的一件事

這個功能錯了畫面不會壞，只會**把甲的作文交到乙的名下**，而且一次是一整班。
所以只要有一點不確定就不自動配，停下來等老師點：兩份塗同一個座號（兩份都不配）、塗兩格、太淡、
座號不在名單上、那位學生已經有作文、缺角。全部決定完「送出」才會亮。
另外，名單上只要有人沒有座號（校務系統沒給）就整份不自動認人，只幫老師分好份。

### 稿紙的變更

- 國中稿紙第 1 頁格子上方靠右、會考第 1 頁右下、學測左上角，都有座號劃記；聯合盃**刻意不加**
  （稿紙上印著「請勿填寫姓名、學校及足以辨識身份之記號」）。
- `apps/web/public/sheets/` 的 PDF 與預覽圖已經重新產生。四角的定位標記沒有動，
  **以前印出去的稿紙照樣能辨識**，只是沒有劃記、整疊掃描時要老師手動指定。

## 四、還沒驗證、已知的限制

- **真的掃描機**（第一節第 3 項）。
- **真的手機上的退回相機**：掃描開不起來時程式會試著直接開手機相機，瀏覽器可能會擋；
  被擋時畫面上還有一顆「改用手機相機」可以按。iPhone、Android 實際是哪一種沒測過。
- **沒有試用名單**：所有老師都看得到「整疊掃描」。1Campus 是用搶先測試名單控制的，聯合報沒有這個機制。
  **要不要先限定幾位老師，想聽你的意見**——要做的話大概是後端一份名單＋前端問一次能不能用。
- 操作手冊與教學影片的截圖還是舊畫面（四顆按鈕），會由我們這邊重拍。
