# 整疊掃描（批次代繳交的另一個入口）

老師把全班的稿紙用掃描機掃成**一份 PDF**，系統照每張稿紙上學生塗的座號分給學生；
老師核對一次，再一次送出。送出之後就是原本的批次代繳交（[ocr-job.md](ocr-job.md)、[grid-ocr.md](grid-ocr.md)），那一段一行都沒改。

2026-11-27 從 1Campus Write 的 `feat/batch-scan`（`22d5671`，那邊還在搶先測試、沒合併進 main）搬來。
**還沒用真的掃描機掃出來的 PDF 測過**，也還沒部署 —— 見最後一節。

---

## 流程

```
批次代繳交視窗 → 右上「整疊掃描」
  1. 選檔      PDF 一份（或一次選好全部的圖片檔）。PDF 只在瀏覽器裡展開成一頁一張圖，不上傳
  2. 讀座號    每 4 張一批 POST /service/instructor/assignments/:id/seat_scan      ← 只讀不寫
                 └─ 後端轉給辨識服務 POST /seat-scan（不用 AI，一頁約 0.5 秒）
  3. 核對      分成一人一份、照座號配好；沒把握的請老師指定或選「不送」，全部決定完才能送
  4. 送出      每位學生排進原本的上傳佇列 → POST /submissions/ocr_proxy（名冊、缺角都在那一支檢查）
               → 老師按「開始辨識」
```

| 位置 | 內容 |
|---|---|
| `services/handwriting-ocr/gaozhi/seatread.py` | 塗卡判讀、表頭截圖、空白頁判斷 |
| `services/handwriting-ocr/gaozhi/service/core.py` 的 `seat_scan` | `/seat-scan` |
| `services/handwriting-ocr/gaozhi/sheet.py` 的 `SEATMARKS` | 座號劃記印在哪（印稿紙與判讀共用） |
| `apps/api/src/lib/seat_scan.ts` | 服務的回應 → 給前端的格式；不認得的一律退成「看不清」 |
| `apps/api/src/routes/instructor.ts` | `POST /assignments/:assignmentId/seat_scan` |
| `apps/web/lib/batchScan.ts` | 分檔、認人、要送出哪些（純邏輯，測試在 `test/batchScan.test.tsx`） |
| `apps/web/lib/pdfPages.ts` | PDF 展開（pdfjs-dist，動態載入） |
| `apps/web/components/BatchScanModal.tsx` | 三步的視窗 |

## 規則：寧可請老師看，也不要分錯人

這個功能錯了畫面不會壞，只會把甲的作文交到乙的名下，而且一次是一整班。所以：

- **自動配好**的條件要全部成立：座號讀得清楚、在名單上、沒有別份塗同一個座號、那位學生還沒有作文也還沒登錄照片。
- 兩份塗成同一個座號 → **兩份都不配**。
- 名單上有人沒有座號、或有重複的座號 → **整份不自動認人**，但仍然分成一人一份，老師看表頭截圖逐份指定
  （1Campus 是整個功能不開放；聯合報的座號來自校務系統同步，常常是空的，所以留著「分檔」這一半）。
- 第 2 頁只接在**緊鄰的前一張第 1 頁**後面；中間夾了認不出來的頁、或種類不同，就自己一份請老師看。
- 缺角（四角的定位標記沒掃到）的那一份不能送，只能重掃或選「不送」—— 送了也會被 `/ocr_proxy` 的檢查擋下來。
- 已經登錄過照片的學生（待辨識、辨識中、已辨識）不會被整疊掃描蓋掉；辨識失敗的可以。

## 還沒做、上線前要確認

1. **用真的掃描機測**：印幾張有劃記的稿紙，請人用 2B 鉛筆或原子筆塗座號，雙面掃成 PDF，走完整個流程。
   目前的測試都是電腦合成的「塗黑橢圓」，沒有真的筆跡、沒有掃描機的歪斜與裁邊。
2. **雲端要重新部署辨識服務**（多了 `/seat-scan`）。API 不需要新的環境變數；`GRID_OCR_SERVICE_URL` 沒設時按鈕還在，
   但讀座號會回「稿紙辨識服務還沒設定」。
3. **沒有試用名單**：1Campus 用搶先測試名單控制誰看得到，聯合報沒有這個機制，所以所有老師都看得到「整疊掃描」。
   要限定的話得另外做。
4. 一次請求 4 張、同時 2 批：是照 API 的 20MB 上限估的，還沒用彩色 300dpi 的大檔量過。
