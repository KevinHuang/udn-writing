# 原稿紅筆（第三階段：老師端）

稿紙代繳交、經過[逐格辨識](grid-ocr.md)的作文，批改頁左邊換成**拉正的原稿**，紅筆畫在學生的字上；
老師在原稿上確認錯字，確認過的才算分、送給[簡易批改](simple-grading.md)的 AI。

這一階段只做**老師端**（使用者決定，2026-11-20）。學生看到的東西不變 —— 發還後學生看自己的原稿加紅筆是下一步。
流程與畫法搬自 1Campus Write 的原稿批改頁（規格書「步驟4_原稿批改頁」、docs/adr/0011）。

---

## 畫面

**左邊**：拉正的原稿（`handwriting_grid_result.page_image_files`），上方可以切回「辨識文字」（原本的樣子、校對也在那裡）。
多頁時一頁接一頁往下排；可以放大到 300%，放大後在框裡按住拖曳。

| 紅筆 | 畫法 | 誰看得到 |
|---|---|---|
| 確定的錯字 | 紅圈，正確的字用楷書寫在行間 | 老師（之後學生） |
| 老師加的錯字 | 同上 | 老師（之後學生） |
| 待確認的錯字 | 紫色虛線圈加「?」 | 只有老師 |
| 否決的錯字、格式提醒 | 灰色虛線 | 只有老師 |
| 格式提醒 | 段首空兩格：紅色折角＋「空兩格」；標點在行首：紅框＋「移上行」 | 老師（之後學生） |
| 亮點 | 行間的綠色波浪線 | 老師（之後學生） |
| 密圈 | 行間的綠色小圈 | 老師（之後學生） |
| 建議 | 左側虛線 | 老師（之後學生） |

紅筆畫在**行間**：聯合報國中稿紙行間 3mm、聯合盃 4mm，和會考稿紙一樣；學測稿紙沒有行間，畫在格子右側裡面。
每個標記有編號（直書的閱讀順序），和右邊的便條一樣，點一下互相跳過去。格式提醒照樣框出位置，但不佔編號。

**右邊**：簡易批改區塊下面是「原稿紅筆」便條，老師可以：

| 對象 | 能做的 | 結果 |
|---|---|---|
| 待確認的錯字 | 是錯字／改正確的字／不是錯字 | 處理完自動跳到下一個待確認 |
| 系統標的錯字 | 改正確的字／不是錯字（可以復原） | |
| 原稿上任何一個字 | 點一下，填正確的字（說明可寫可不寫） | 算確定的錯別字，標「老師加的」 |
| 老師加的錯字 | 改正確的字／刪掉 | |
| 格式提醒 | 不是格式問題（可以復原） | |

- **每按一下就存**（`manuscript_mark_decision`，migration 013），和批改結果分開：重置批改不會清掉。
- **發還之後鎖住**（API 回 409），要改先收回發還：批改頁「已發還」旁邊的「收回發還」
  （`POST /service/instructor/submission_feedback/unreturn`）。退回已批改，分數與評語留著、不產生新版本；
  學生端在再次發還之前看不到這一篇的成績。只做單筆，清單頁沒有批次收回（整班一起收回太容易誤按）。
- 按「AI 批改」時還有待確認的錯字，先提醒（不擋）：確認過的才算分、送 AI，先看完就不用因為錯字重新評分。

## 「確定的錯別字」只有一份

系統有把握、老師沒有否決的錯字，加上老師確認的、老師加的（`apps/api/src/lib/manuscript/marks.ts` 的 `mergeManuscriptMarks`）。
原稿畫面、送簡易批改 AI 的錯字清單、批改頁的辨識摘要、重新評分的基準，都用這一份。
**待確認的不算分、不送 AI。**

重複的錯字標記只算一個（`dedupeMarks`）：同一格被標兩次、或錯字表和 AI 對同一個詞建議同一個字卻標在隔壁格，留錯字表的。

## 老師加的錯字落在卡片引用上

通常是辨識把學生寫錯的字讀成了正確的字，系統以為這句沒問題就給了卡片。老師加了錯字之後：
密圈整張先拿掉；亮點、建議只拿掉引用和畫線；成語只拿掉那一個。刪掉那個錯字就恢復。
評語裡也提到那句時，只提醒老師自己看，不自動改字（評語是老師可以改的文字）。

## 重新評分

批改當下的錯字狀態存在 `simple_grading_result.detail.baseline`。之後老師改了錯字或格式，
「**3 個以上錯字或段首沒空兩格**」這條和批改時不同（變成符合、或不再符合）就在批改面板提醒「重新評分」。
- 3 個是 1Campus 會考版定下的門檻；聯合報的批改規範把錯別字與格式放在第四向度，4 級分的描述是「有一些錯別字及格式（如段首未縮排兩格）」，先沿用。
- 按下去先確認，再用目前確定的錯字重跑一次簡易批改，**存成新的一版：級分與評語都換掉**（老師改過的評語也會被換掉）。
  1Campus 是只換分數、卡片不動；這邊的卡片併在評語裡，沒辦法只換一半。
- 舊的批改結果沒有基準，不提醒。

## 稿紙上的批改區（聯合報國中稿紙第二頁）

聯合報國中寫作稿紙的第二頁左側印了三個給老師填的區塊。原稿畫面直接把批改內容用紅筆、楷書填進去（使用者提案，2026-11-23）。
**只有聯合報國中稿紙（`udn`）有**；聯合盃、會考、學測稿紙沒有這一區。圖例裡多一項「稿紙上的批改區」，可以暫時隱藏（看照片上原本寫了什麼）。

| 區塊 | 填什麼 | 規則 |
|---|---|---|
| 錯字訂正（6 行 × 6 格） | **確定的錯字**正確的字，每行最上面一格，下面留給學生練習 | 依直書的閱讀順序、同一個字只寫一次；待確認、否決的不放。正確的字是一個詞時一格一個字往下排。超過 6 個只放前 6 個，那一頁下面提醒老師還有幾個 |
| 寫作能力分析（四向度 × 四等第） | 四向度各打一個勾 | **6 級分極佳、5 級分佳、4 級分尚可、3 級分以下待加強**（使用者決定）。0 級分、沒有四向度的舊批改不打勾 |
| 老師評語 | 評語裡**第一個小標題之前**的那一段（簡易批改的總評，100～150 字），直寫、由右而左 | 亮點、建議卡片放不進來。字先用 5mm，放不下縮到最小 3.2mm（約 370 字），再放不下截斷加刪節號，並在那一頁下面提醒 |

- **內容用畫面上當下的批改結果組**（`apps/web/lib/gradingZone.ts`）：老師改評語、確認錯字，稿紙上馬上跟著變，不用等存檔。沒有另外存一份。
- **位置由後端算**（`apps/api/src/lib/manuscript/grading_zone.ts`）：批改區每一格在稿紙上的 mm 量自 `udn_original.pdf` 的向量檔，
  再用那一頁所有格子（含空白格）的像素位置反推「mm → 像素」。這樣 A3、B4（版面縮成 86.5%）都對得上，也順便確認這一頁真的是第二頁的版面
  （第一頁的作答格在左邊 76mm，對不上就不畫）。**稿紙改版時，那個檔的座標要和 `templates/udn.json` 一起改。**
- **直寫的標點**：全字庫正楷體的標點照台灣標準放在字框正中間，逗號、句號直接用；引號、括號、破折號、刪節號轉 90 度；半形英數換成全形。
  沒有用字型的直排替換 —— 網頁用的字型檔沒有留那些字。
- **第四向度 5、6 級分怎麼分**寫在簡易批改的提示詞裡（第 2 版）：共用的四向度規準把這兩級寫在同一條，稿紙上卻要分成極佳和佳。
  清單上沒有錯別字、格式檢查沒有問題、標點都對才給 6。
  **這一句只加在簡易批改的提示詞**（使用者指定，2026-11-23）：那一份只用在原稿批改（稿紙代繳交、逐格辨識、文字沒被校對過）。
  其他作文走一般批改，提示詞與回饋維持原樣，共用的 `SUB_SCORE_RUBRIC` 也不能為了稿紙去改（`simple_grading.test.ts` 有測試釘住）。
  老師校對過文字的稿紙作文也是走一般批改，所以那種作文第四向度的 5、6 級分沒有這條規則。

### 只寫一頁：補一頁空白稿紙

學生只寫了一頁、沒有拍第二頁時，沒有任何一頁對得上批改區。這時原稿最下面補一頁**空白稿紙的第二頁**，批改區畫在那上面
（標「批改區（這份作文沒有第二頁的照片，放在空白稿紙的第二頁上）」；圖例裡把批改區隱藏時，整頁不出現）。

- 底圖：`apps/web/public/sheets/udn_A3_p2_grading.png`（A3 原尺寸、整張紙、每 mm 8 個像素、灰階，約 76KB），
  由 `services/handwriting-ocr/tools/build_static_sheets.py` 產生 —— 重跑那支腳本會一起更新。
- 位置：後端回 `blankGradingZone`（`{ pxPerMm, zone }`，稿紙上的 mm 直接乘 8），只有「沒有任何一頁有批改區」時才給。
  前端手上的底圖解析度（`BLANK_GRADING_SHEETS`）和它不一樣就不補；前端的測試會量底圖的寬高。**改解析度要三個地方一起改。**
- 有一頁對得上就不補：批改區只畫一次，畫在學生真的那張紙上。

## API（只給老師；學生端沒有）

| 端點 | 用途 |
|---|---|
| `GET /service/instructor/grading/:id/manuscript` | 每頁拉正的圖、有字的格子位置（圖上的像素）、合併後的標記、目前的錯字狀態；每頁另有 `gradingZone`（批改區每一格的像素位置，沒有就是 null），都沒有時另給 `blankGradingZone`（空白稿紙第二頁上的位置）。沒有逐格辨識回 `{ available: false }` |
| `GET .../manuscript/pages/:n` | 拉正的稿紙圖。用伺服器的 GCS 權限讀（bucket 之後不公開也能用；本機假儲存也讀得到），`Cache-Control: private` |
| `POST .../manuscript/decisions` | `{ target, cellKey, action, correct?, note? }`，回傳更新後的標記。標記已經變了回 409、說不通的動作回 400 |
| `POST /service/instructor/grading/:id/regrade` | 重新評分。還沒用簡易批改批過、已發還都回 409 |

範圍一律走 `courseScopeOf`：別班的老師 404。

## 楷書字型

正確的字用**全字庫正楷體**（數位發展部，依台灣國家標準字形）：學生照著紅字訂正，字形一定要是台灣標準寫法
（1Campus 用過悠哉字體，「啟」被畫成「啓」才改的）。

- 字型檔：`apps/web/public/fonts/tw-kai/`（只留 Big5 常用＋次常用字，切成 133 塊 woff2，約 9MB；瀏覽器只下載畫面上用到的字）。
  第一次打開原稿才載入。從 1Campus Write 複製；全字庫改版時用 `services/handwriting-ocr/tools/build_tw_kai_web.py` 重新產生。
- 授權：全字庫可擇一用政府資料開放授權條款或 **SIL OFL 1.1**，這裡用 OFL 1.1，全文 `apps/web/public/licenses/tw-kai-font-OFL.txt`。
  不用教育部標準楷書：它的授權是 CC 姓名標示－禁止改作，切成小檔算改作。

## 部署

正式庫依序套 011、012、`013-manuscript-mark-decision.sql`（**都要在程式上線之前**）。不用新的環境變數。

## 還沒做

- **學生端**：發還後學生看自己的原稿加紅筆、不再看辨識文字（1Campus 的「我的原稿」），連帶下載報告、AI 學習分析怎麼處理。
- 批次批改（批改清單一次批全班）還有待確認的錯字時，沒有先提醒（單份「AI 批改」有）。
- 名冊上標「錯字待確認 N」、原稿頁「下一份」（1Campus 的兩段式：先全班看錯字，再一次批改）。
- 實際印出來、手寫、拍照的稿紙還沒走過一次（本機的測試稿紙是模擬的，辨識文字是模擬 AI 填的）。
- 稿紙上的批改區：
  - **真的第二頁照片還沒走過**：只寫一頁的情況（補空白稿紙）在批改頁用開發庫的示範作文實測過，位置和印的格子對齊；
    有拍第二頁的情況，後端的位置只用模擬的格子測，實拍、拉正之後勾會不會剛好落在格子裡，要有真的照片才知道。
  - 老師改不了四向度（只會沿用 AI 給的）：老師把整體級分改掉，稿紙上的勾不會跟著變。
  - 列印、學生端還沒有：現在只有老師在批改頁看得到。
